Tanggal: 2026-11-18
Penyusun: Claude (persona Principal Engineer + DevOps Engineer)
Narasumber: user (project manager; persetujuan diteruskan ke CEO dan CTO)
Cara bertanya: satu pertanyaan per giliran. Setiap pertanyaan ditulis lengkap di chat beserta konteks dan arti pilihan sebelum dialog pilihan ditampilkan.

## Pertanyaan dan jawaban

**T5-Q1. Bahasa dan framework apa yang dipakai untuk backend (Rumah Sehat dan RME minimalis) dan tiga aplikasi web (backoffice, portal rekanan, web RME)?** (konteks: Flutter wajib untuk mobile (brief P7.4); tim PM, Claude, 1 mobile developer; backend dan web ditulis Claude; backend harus mendukung SQL eksplisit PostgreSQL, antrean job di PostgreSQL, WebSocket, validasi token Keycloak, SDK KMS, OpenAPI. Pilihan awal: (1) TypeScript/Node.js + NestJS, web React (rekomendasi penyusun); (2) Go + React; (3) Kotlin/Spring Boot + React; (4) Dart + Flutter Web)
- Jawaban pertama (teks bebas): "bagaimana bika RUST untuk BE, Next.js untuk FE dan Flutter untuk mobile apps".
- Tanggapan penyusun: Rust layak (aman memori, kebutuhan memori kecil, compiler ketat; tetapi pengembangan lebih lambat dan pemelihara harus menguasai Rust, PT-19). Next.js layak dengan server Next.js berperan sebagai BFF (ADR-011 butir 7), sehingga server Next.js masuk modul kritis T1 dan ketiga web berjalan sebagai proses server Node di server Indonesia. Riwayat keamanan dari halaman advisory resmi Next.js: dua advisory Critical (RCE di `next/og` ImageResponse 22 Sep 2026; RCE di Image Optimization dengan SVG 14 Okt 2026) dan tujuh Moderate pada 3 Nov 2026. Mitigasi: fitur yang tidak dipakai dimatikan, versi dipin, patch cepat. Pilihan diulang: (1) TypeScript NestJS + Next.js (rekomendasi); (2) Rust + Next.js; (3) Rust + React SPA; (4) TypeScript NestJS + React SPA.
- Pertanyaan user: "lebih lambat dikembangkan ini maksdnya bagaimana?". Penyusun menjelaskan tiga sebab (waktu compile pada setiap siklus verifikasi dan CI; compiler ketat yang menuntut lebih banyak putaran perbaikan; lebih banyak komponen yang mungkin ditulis sendiri) dan dampaknya ke scope yang muat sebelum 1 Maret 2027 dengan toleransi waktu 0; besaran perlambatan `[TIDAK DIKETAHUI]`, diukur di reference implementation Tahap 8 Fase 1.
- Jawaban (T5-Q1): "Rust + Next.js".
- Catatan penyusun: backend Rumah Sehat dan RME minimalis memakai Rust; backoffice, portal rekanan, dan web RME memakai Next.js dengan server Next.js sebagai BFF; aplikasi mobile Flutter. Versi dan pustaka diverifikasi ke registry resmi sebelum ditulis di `docs/05-stack.md`. Perubahan penempatan BFF dari "backend" ke server Next.js dicatat sebagai tafsiran ADR-011 butir 7 untuk ditampilkan di gate.

**Masukan user (di tengah T5-Q1):** "vpsnya hostinger dan biznet gio saja".
- Catatan penyusun: masukan ini bertentangan dengan ADR-019 (platform kontainer dan PostgreSQL terkelola; "server virtual yang dikelola sendiri tanpa layanan terkelola" termasuk alternatif yang ditolak) dan berdampak ke ADR-009 (WORM), ADR-013 (KMS), ADR-021 (IAM dan log audit penyedia). Kemampuan Hostinger dan Biznet Gio sedang diverifikasi ke sumber resmi; konsekuensinya diajukan sebagai T5-Q2 dan, bila disetujui, sebagai change request.

**T5-Q2. Bagaimana VPS Hostinger dan Biznet Gio dipakai?** (konteks yang disampaikan, dari halaman resmi yang dibuka 2026-11-18 (`docs/sources.md`): Hostinger punya lokasi VPS di Indonesia (Jakarta), paket KVM 1–8, tanpa object storage, database terkelola, load balancer, KMS, atau secret manager di halaman yang dibuka; Biznet Gio punya data center Indonesia, NEO Lite/Lite Pro, NEO Object Storage kompatibel S3 dengan URL bertanda tangan dan Object Lock (WORM), NEO App dengan PostgreSQL 14–16 terkelola (PITR/standby belum terverifikasi), load balancer, jaringan privat, firewall; KMS, secret manager, log terkelola, WAF, Redis terkelola tidak ditemukan. Dampak terhadap ADR-019 (VPS kelola sendiri adalah alternatif yang ditolak), ADR-013 (KMS diganti OpenBao yang dijalankan sendiri; kehilangan kunci pembuka = data klinis tidak terbaca), ADR-009 (WORM tetap lewat Object Lock Biznet Gio), ADR-021 (bastion SSH ber-MFA dan log audit OpenBao menggantikan IAM/log audit penyedia), ADR-010 (log dan pemantauan dijalankan sendiri), beban operasional dan R-04 naik, PT-18; dicatat sebagai CR-012. Biaya cloud terkelola belum dihitung. Pilihan: (1) Biznet Gio utama + Hostinger cadangan (rekomendasi penyusun dalam arah VPS); (2) hanya Biznet Gio; (3) Hostinger utama + Biznet Gio object storage; (4) tetap cloud terkelola, ADR-019 tidak berubah)
Jawaban: "Biznet utama+Hostinger (Recommended)".
Catatan penyusun: Biznet Gio menjalankan aplikasi, database utama, Keycloak, Redis, OpenBao, dan object storage (WORM, backup); Hostinger Jakarta menjalankan database standby dan salinan backup terenkripsi sebagai lokasi kedua; replikasi antar-penyedia lewat jalur terenkripsi. Diterapkan sebagai CR-012 (ADR-019, ADR-013, ADR-021, ADR-010, ADR-009).

**T5-Q3. Payment gateway mana yang dijadikan kandidat utama?** (konteks: syarat ADR-015/AB-21; temuan dokumentasi resmi 2026-11-18: Xendit xenPlatform membagi dana ke saldo sub-akun lalu ditarik ke bank, fee platform dalam transaksi yang sama, refund ke metode asal, token callback, izin BI tidak terverifikasi dari situs; Midtrans refund penuh/parsial dan tanda tangan SHA512, split dan izin BI tidak terverifikasi; DOKU menyatakan "PJP Level 1", split settlement langsung ke beberapa rekening bank, refund penuh/parsial; lokasi data ketiganya tidak disebut di dokumentasi publik dan harus dikonfirmasi tertulis; MDR dan kontrak keputusan bisnis; adaptor ADR-015 memungkinkan penggantian. Pilihan: (1) DOKU utama, Xendit cadangan (rekomendasi penyusun); (2) Xendit utama, DOKU cadangan; (3) Midtrans utama; (4) tunda sampai jawaban tertulis ketiganya)
Jawaban: "DOKU utama, Xendit cadangan (Recommended)".
Catatan penyusun: adaptor DOKU dibangun lebih dulu. Keputusan final setelah konfirmasi tertulis vendor atas lokasi pemrosesan dan penyimpanan data, nomor izin BI, mekanisme split settlement untuk markup dan bagian rekanan, refund dari dana yang sudah terbagi (PT-27), dan biaya (pertanyaan terbuka baru untuk user/CEO).

**T5-Q4. Email notifikasi dikirim lewat apa?** (konteks: email satu-satunya kanal di luar aplikasi sejak CR-007; penyedia wajib di Indonesia (T4-Q1); isi tanpa data kesehatan rinci (AB-73); pesan yang sudah terkirim tersimpan di penyedia kotak surat milik penerima. Temuan: Amazon SES tersedia di region Jakarta ap-southeast-3 lewat API, endpoint SMTP tidak tersedia di Jakarta; KIRIM.EMAIL (Bandung) API dan lokasi data tidak terbaca; Biznet Gio dan Hostinger tidak ditemukan menyediakan email transaksional. Pilihan: (1) Amazon SES Jakarta lewat API (rekomendasi penyusun); (2) KIRIM.EMAIL; (3) server email sendiri di VPS)
Jawaban: "Amazon SES Jakarta (Recommended)".
Catatan penyusun: adaptor email memakai API SES region ap-southeast-3 (bukan SMTP), dengan akun AWS khusus email berhak minimum. Lokasi pemrosesan SES di region dicatat di `docs/05-stack.md`.

**T5-Q5. Integrasi kurir untuk pesanan produk memakai apa?** (konteks: US-703 AC3 pilihan kurir dan ongkir dari kurir terintegrasi; status Dikirim/Terkirim/Gagal dari kurir; PT-29 dan PT-31 terbuka. Temuan dokumentasi resmi 2026-11-18: Biteship agregator 30+ kurir, API tarif dan order, order dibayar dari saldo deposit, rincian webhook tidak terbaca; Lalamove kurir instan, Indonesia didukung, API quotation dan order, webhook bertanda tangan HMAC-SHA256; lokasi data keduanya tidak disebut, perlu konfirmasi tertulis. Pilihan: (1) Biteship utama (rekomendasi penyusun); (2) Lalamove saja; (3) Biteship + Lalamove; (4) tunda sampai PT-29/PT-31)
Jawaban: "Lalamove saja".
Catatan penyusun: adaptor kurir dibangun untuk Lalamove. Konsekuensi yang disampaikan: pengiriman produk hanya layanan instan Lalamove di area layanannya; "pilihan kurir" di US-703 AC3 berupa jenis layanan/kendaraan Lalamove yang tersedia untuk alamat itu; alamat di luar area layanan membuat checkout tidak dapat dilanjutkan (US-703 AC3). Keputusan final setelah konfirmasi tertulis lokasi data.

**T5-Q6. Di mana kode disimpan dan pipeline CI/CD dijalankan?** (konteks: repositori di GitHub (privat, di luar Indonesia); pipeline hanya kode dan data sintetis (ADR-019 butir 2); T4-Q1 mengatur penyedia yang memproses data pengguna, sehingga pemakaian GitHub dimintakan penegasan; syarat ADR-021 butir 4; dengan VPS tidak ada federasi identitas cloud. Pilihan: (1) GitHub untuk kode dan CI, deploy lewat agen di VPS yang menarik image berdasarkan digest setelah persetujuan manual, tanpa kunci SSH production di GitHub (rekomendasi penyusun); (2) GitHub penuh dengan deploy lewat SSH (kredensial statis, melemahkan ADR-021); (3) Git server dan CI sendiri di VPS Biznet Gio)
Jawaban: "GitHub + agen deploy VPS (Recommended)".
Catatan penyusun: GitHub (repositori, Actions, registry image) dipakai untuk kode dan data sintetis saja; data pribadi tidak pernah masuk pipeline, repositori, atau image. Deploy dilakukan agen di VPS Biznet Gio. Pengaturan proteksi branch dan environment approval dibuat user (ADR-021 konsekuensi).

**T5-Q7. Apakah mobile developer dibayar penuh waktu selama pembangunan, dan apakah tetap dipertahankan setelah go-live? (PT-19)** (konteks: Business Case §6.1 Rp10–20 juta/bulan (T1-Q5a): Rp34–68 juta sampai go-live dan Rp120–240 juta untuk 12 bulan operasi, berlaku bila penuh waktu sepanjang periode; masuk baseline biaya acuan toleransi +20% (T1-Q8); pemeliharaan setelah go-live makin penting dengan backend Rust di VPS kelola sendiri. Pilihan: (1) penuh waktu dan dipertahankan; (2) penuh waktu sampai go-live; (3) paruh waktu/per proyek; (4) belum diketahui)
Jawaban: "Penuh waktu sampai go-live".
Catatan penyusun: PT-19 terjawab. Biaya developer sampai go-live Rp34–68 juta (Business Case §6.1); biaya developer setelah go-live tidak termasuk baseline. Siapa yang memelihara aplikasi mobile, backend Rust, dan infrastruktur VPS setelah go-live dicatat sebagai pertanyaan terbuka baru (PT-35).

**T5-Q8. Bagaimana persetujuan manual untuk deploy production dijalankan?** (konteks: ADR-021 butir 4 mensyaratkan deploy production dari `main` dengan review yang tidak dapat dilewati dan persetujuan manual; dokumentasi GitHub (2026-11-18): "If you are on a GitHub Free, GitHub Pro, or GitHub Team plan, other deployment protection rules, such as a wait timer or required reviewers, are only available for public repositories."; repositori privat milik akun pribadi, paket tidak terbaca; alur runbook: Claude commit/merge/push setelah verifikasi hijau. Pilihan: (1) persetujuan di sisi VPS: staging otomatis, production dipicu orang kedua berwenang lewat bastion dengan sertifikat SSH berumur pendek dari OpenBao ber-MFA, mendeploy digest yang lulus staging, tercatat di log audit OpenBao (rekomendasi penyusun); (2) pindah ke GitHub Enterprise; (3) tanpa persetujuan manual)
Jawaban: "Persetujuan di sisi VPS (Recommended)".
Catatan penyusun: diterapkan di `docs/05-stack.md` §CI/CD dan CR-012 (penyesuaian cara memenuhi ADR-021 butir 4). Orang kedua yang berwenang (CTO dan/atau user) dan prosedurnya ditetapkan sebelum go-live (ADR-021 konsekuensi).

**T5-Q9. Berapa biaya tim selain mobile developer yang masuk baseline biaya? (PT-18)** (konteks: PM, langganan Claude, staf operasional admin termasuk siaga di luar jam kerja yang makin diperlukan dengan VPS kelola sendiri; tenggat dipindah ke gate Tahap 5 (T4-G4); baseline menjadi acuan toleransi +20% (T1-Q8). Pilihan: (1) isi sekarang; (2) di luar anggaran proyek; (3) belum diketahui, tenggat Tahap 7)

**T5-Q10. Berapa anggaran dan waktu untuk perizinan, legal, dan kepatuhan? (PT-25)** (konteks: konsultan hukum, PSE, perizinan berusaha, kemungkinan PSEF, DPIA, petugas PDP (BRD §6); tenggat gate Tahap 5 (T4-G4); PT-20 belum ditunjuk, banyak keputusan menunggu legal ditambah konfirmasi vendor dan Magic Transit. Pilihan: (1) isi sekarang; (2) di luar anggaran proyek, waktu tetap dipantau sebagai risiko; (3) belum diketahui, tenggat Tahap 7)
Jawaban: "Di luar anggaran proyek".
Catatan penyusun: anggaran PT-25 terjawab sebagai di luar baseline biaya proyek. Waktu perizinan dan legal tetap `[TIDAK DIKETAHUI]` dan dipantau sebagai risiko jadwal (syarat go-live izin tidak dapat dikurangi, Business Case §7.1).

**T5-Q11. Bagaimana perlakuan pajak atas markup dan pembagian dana langsung? (PT-28)** (konteks: pemilik CEO + konsultan pajak; tenggat gate Tahap 5 (T4-G4); jurnal dapat menampung akun pajak tanpa perubahan struktur (ADR-015); memengaruhi harga tampil, bukti bayar, laporan keuangan, sehingga harus jelas sebelum EP-08. Pilihan: (1) sudah ada arahan; (2) belum, tenggat sebelum EP-08; (3) belum, tenggat Tahap 7)
Jawaban pilihan: "Sudah ada (tulis di Other)" tanpa teks. Penyusun meminta ringkasan.
Jawaban teks: "sama seperti layanan lainnya, karena markup dulu baru dibebakan pajaknya."

**T5-Q11a. Bagaimana pajak masuk ke harga yang dibayar pasien?** (konteks: rumus harga saat ini total = harga rekanan + markup + ongkir + biaya transaksi (AB-11, AB-12, ADR-015 butir 3), tanpa komponen pajak. Pilihan: (1) pajak dihitung dari (harga rekanan + markup) dan ditambahkan ke total, baris pajak tampil terpisah; (2) pajak hanya atas markup; (3) harga sudah termasuk pajak)
Jawaban: "Di atas harga rekanan+markup".
Catatan penyusun: PT-28 terjawab sebagian. Pajak dihitung dari (harga rekanan + markup) setelah markup diterapkan, ditambahkan ke total yang dibayar pasien, dan tampil sebagai baris terpisah di rincian harga. Jenis pajak, tarif, dasar pengenaan untuk ongkir dan biaya transaksi, pihak pemungut/penyetor, dan isi bukti bayar `[TIDAK DIKETAHUI]` (PT-28 sisa, pemilik CEO + konsultan pajak, tenggat sebelum pengembangan EP-08). Tarif dijadikan parameter berlaku-mulai yang diatur Keuangan. Perubahan rumus harga dicatat sebagai CR-013 (PRD AB-11/AB-12, US-801/US-812, harga terkunci ADR-015 butir 3, jurnal akun pajak).
